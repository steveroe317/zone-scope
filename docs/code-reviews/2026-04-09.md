# ZoneScope Code Review — 2026-04-09

## Overview

Full review of the ZoneScope codebase against the Swift/SwiftUI style guidelines in `AGENTS.md`. The project targets iOS 26.0+, Swift 6.2+, and has `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` set in build settings.

**Files reviewed:**
- `ZoneScopeApp.swift`
- `ContentView.swift`
- `AuthPromptView.swift`
- `ZoneChartView.swift`
- `ZoneRowView.swift`
- `TimeFormatting.swift`
- `HealthKitManager.swift`

---

## What's in good shape

- `@MainActor @Observable final class HealthKitManager` — correctly annotated
- Modern async/await throughout; no `DispatchQueue` or closure-based concurrency
- `NavigationStack`, `ContentUnavailableView`, `.task`, and other modern SwiftUI APIs used correctly
- `onChange(of:)` uses the two-parameter variant
- `formatTime` uses `Duration.formatted(.time(pattern:))` — no C-style `String(format:)`
- Views split into separate files
- No third-party dependencies
- Scene phase monitoring with a 15-minute refresh guard

## Issues

### High

#### Force unwraps — `HealthKitManager.swift`

Multiple force unwraps on `HKObjectType` lookups that should use safe unwrapping.

**`requestAuthorization()` (lines 88–91):**
```swift
// Current
let typesToRead: Set<HKObjectType> = [
    HKObjectType.quantityType(forIdentifier: .heartRate)!,
    HKObjectType.quantityType(forIdentifier: .restingHeartRate)!,
    HKObjectType.workoutType(),
    HKObjectType.characteristicType(forIdentifier: .dateOfBirth)!
]

// Fix
guard
    let heartRateType    = HKObjectType.quantityType(forIdentifier: .heartRate),
    let restingHRType    = HKObjectType.quantityType(forIdentifier: .restingHeartRate),
    let dobType          = HKObjectType.characteristicType(forIdentifier: .dateOfBirth)
else { return }

let typesToRead: Set<HKObjectType> = [heartRateType, restingHRType, HKObjectType.workoutType(), dobType]
```

**`fetchHRZoneMinutes(for:)` (line 258):**
```swift
// Current
sampleType: HKObjectType.quantityType(forIdentifier: .heartRate)!,

// Fix
guard let heartRateType = HKObjectType.quantityType(forIdentifier: .heartRate) else {
    return ZoneMinutes()
}
// use heartRateType in query
```

**`TimePeriod.startDate` (lines 26, 28, 30):**
```swift
// Current
return calendar.date(byAdding: .day, value: -7, to: now)!

// Fix
return calendar.date(byAdding: .day, value: -7, to: now) ?? now
```

#### `Array(zones.enumerated())` — `ZoneChartView.swift:41`

AGENTS.md: *"When making a `ForEach` out of an `enumerated` sequence, do not convert it to an array first."*

```swift
// Current
ForEach(Array(zones.enumerated()), id: \.element.0) { index, zoneInfo in

// Fix
ForEach(zones.enumerated(), id: \.element.0) { index, zoneInfo in
```

### Medium

#### `TimePeriod` and `ZoneMinutes` in the wrong file — `HealthKitManager.swift`

Both are standalone data types that happen to live in `HealthKitManager.swift`. AGENTS.md: *"Break different types up into different Swift files."* `CachedWorkout` is `private` to the file and can stay.

**Fix:** Move `TimePeriod` to `TimePeriod.swift` and `ZoneMinutes` to `ZoneMinutes.swift`.

---

#### `zones` should be `static let` — `ZoneChartView.swift:15`

`zones` is a constant array of static data. As a `let` instance property it is allocated for every view instance.

```swift
// Current
private let zones: [(Int, String, Color)] = [...]

// Fix
private static let zones: [(Int, String, Color)] = [...]
```

---

#### Hardcoded frame widths — `ZoneRowView.swift:27, 52`

Fixed widths of 80 and 75 points clip at larger Dynamic Type sizes and don't adapt to locale differences in text length.

```swift
.frame(width: 80, alignment: .leading)  // label column
.frame(width: 75, alignment: .trailing) // time/BPM column
```

**Fix:** Replace the `HStack` + fixed-frame layout with a `Grid`, which distributes column widths based on content.

---

### Low

#### Hardcoded font size — `AuthPromptView.swift:16`

AGENTS.md: *"Do not force specific font sizes; prefer using Dynamic Type."*

```swift
// Current
.font(.system(size: 60))

// Fix — respects the user's preferred text size
.font(.system(.largeTitle))
.imageScale(.large)
```

For a purely decorative icon in an empty state this is a minor accessibility concern rather than a functional bug.
